# چک‌لیست تکمیل نمونهٔ مدیریتی ERP

این سند مسیر ارتقای نمونهٔ مستقل Django را مشخص می‌کند. هدف، یک ارائهٔ تمیز و صادقانه از جریان‌های اصلی ERPNext است تا مدیر بتواند درباره ادامهٔ سرمایه‌گذاری تصمیم بگیرد. انجام هر مرحله فقط با درخواست شما شروع می‌شود؛ می‌توانید بگویید «مرحلهٔ ۲ را انجام بده».

## قاعدهٔ اجرای هر مرحله

- [ ] محدودهٔ همان مرحله و سناریوی پذیرش آن پیش از کدنویسی روشن باشد.
- [ ] تغییرها فقط در `erpnext_django_demo` انجام شوند، مگر اینکه شما صریحا محدوده را گسترش دهید؛ `django_port` مستقل بماند.
- [ ] کد، مهاجرت پایگاه‌داده، دادهٔ نمونه و راهنما در صورت نیاز با هم به‌روز شوند.
- [ ] آزمون‌های مرتبط و `manage.py check` اجرا شوند؛ صفحه‌های تغییرکرده در مرورگر بررسی شوند.
- [ ] نتیجهٔ هر مرحله با یک commit مشخص در همین مخزن و شاخهٔ کاری ثبت شود؛ شناسهٔ commit و نتیجهٔ آزمون در پاسخ به شما اعلام شود.
- [ ] فقط پس از برآورده شدن معیار پذیرش، تیک‌های مرحله زده شوند. مورد ناتمام با توضیح روشن باقی بماند.

- [x] مدل‌های مشتری، تامین‌کننده، کالا، سفارش و گردش موجودی ایجاد شدند.
- [x] داشبورد فارسی، فهرست‌ها، فرم‌ها و صفحات سفارش آماده شدند.
- [x] دادهٔ نمایشی تکرارپذیر و راه‌انداز PowerShell اضافه شدند.
- [x] تایید سفارش فروش و خرید، موجودی را با ثبت گردش تغییر می‌دهد.
- [x] آزمون‌های فعلی گذشتند و نمای داشبورد در مرورگر بررسی شد.

**خروجی:** نمونهٔ قابل اجرا در رایانهٔ محلی. **Commit:** `91cec12c0b`.

## مرحلهٔ ۱ — تعریف ارائه و معیار موفقیت

- [x] مخاطب جلسه، نوع کسب‌وکار، سه مسئلهٔ اصلی و تصمیم مورد انتظار مدیر ثبت شود.
- [x] اصطلاحات، واحد پول، تقویم، نام شرکت و محرمانگی دادهٔ نمایش به‌صورت واقعی یا فرض‌های قابل جایگزین ثبت شوند.
- [x] سه سناریوی اولویت‌دار انتخاب شوند: فروش تا دریافت، خرید تا تامین، و کنترل موجودی؛ هر کدام نقطهٔ شروع و نتیجهٔ قابل مشاهده داشته باشند.
- [x] قابلیت‌های نسخهٔ نمایشی، قابلیت‌های فاز اجرای واقعی و موارد خارج از محدوده جدا شوند.
- [x] شاخص‌های موفقیت ارائه تعریف شوند؛ مثلا اجرای سناریو بدون خطا، صحت اعداد و فهم جریان توسط مدیر.
- [x] نگاشت مفاهیم نمونه به DocTypeهای مرتبط ERPNext و تفاوت‌های عمده مستند شود.

**معیار پذیرش:** یک سناریونامهٔ کوتاه و فهرست محدوده وجود داشته باشد که بتوان با آن ارائه را تمرین کرد. اگر اطلاعات شرکت هنوز در دسترس نبود، فرض‌ها شفاف و قابل جایگزینی نوشته شوند.

**سند پذیرش:** [طرح ارائه و محدوده](docs/PRESENTATION_PLAN.md). شخصی‌سازی با اطلاعات واقعی شرکت همچنان باز است.

- [x] قلم فارسی به‌شکل پایدار و بدون وابستگی ضروری به اینترنت بارگذاری شود.

- [x] صفحه‌های دسکتاپ و موبایل برای داشبورد، جدول‌ها، فرم‌ها و جزئیات سفارش بازبینی شوند.
- [x] وضعیت‌های خالی، خطا، موفقیت، هشدار و بارگذاری طراحی و متن‌های آنها بازنویسی شوند.
- [x] کنترل‌های فرم، ناوبری با صفحه‌کلید، کنتراست و برچسب‌های دسترس‌پذیری بررسی شوند.
- [x] هیچ عدد، دکمه یا نمودار نمایشی بدون معنی یا مسیر قابل توضیح باقی نماند.
- [x] تصویرهای به‌روز از صفحات اصلی و نسخهٔ موبایل در راهنما ثبت شوند.

**معیار پذیرش:** ارائه در اندازهٔ معمول لپ‌تاپ و موبایل خوانا باشد؛ مدیر در کمتر از چند ثانیه بتواند جای فروش، خرید و انبار را پیدا کند.

**شواهد:** [دسکتاپ](docs/dashboard.png)، [موبایل](docs/mobile.png)، [فرم سفارش](docs/order-form.png)، [جزئیات سفارش](docs/order-detail.png). قلم محلی بارگذاری شد و عرض صفحهٔ موبایل در مرورگر کنترل شد.

**معیار پذیرش:** کاربر بتواند یک مشتری و کالا را ایجاد، پیدا و اصلاح کند و سفارش‌های قبلی همچنان درست نمایش داده شوند.

**شواهد:** [فهرست کالاها](docs/items.png)، [نمای موبایل کالاها](docs/items-mobile.png)، [پروندهٔ مشتری](docs/customer-detail.png)، [ویرایش کالا](docs/item-edit.png). آزمون‌ها حفظ سابقه، کد یکتا، ویرایش بدون تغییر موجودی و صفحه‌بندی را پوشش می‌دهند.

- [x] چرخهٔ فروش با وضعیت‌های روشن طراحی شود: پیش‌نویس، تایید، تحویل، صورتحساب، دریافت و لغو مجاز.
- [x] اقلام سفارش قابل افزودن و ویرایش باشند؛ مبلغ کل، قیمت ثبت‌شده و اعتبار موجودی دقیق محاسبه شوند.
- [x] تحویل کالا از انبار و جلوگیری از تحویل یا کسر موجودی دوباره پیاده‌سازی شود.
- [x] صورتحساب و دریافت وجه در سطح مناسب نمونهٔ نمایشی اضافه شوند؛ ماندهٔ قابل دریافت مشخص باشد.
- [x] صفحهٔ جزئیات، خط زمانی رویدادها و نسخهٔ قابل چاپ سفارش/صورتحساب آماده شود.
- [x] خطاهای جریان، مانند موجودی ناکافی یا اقدام تکراری، با پیام روشن مدیریت شوند.

**معیار پذیرش:** در ارائه بتوان از ثبت سفارش مشتری تا تحویل و ثبت دریافت پیش رفت؛ اعداد و موجودی در همهٔ صفحه‌ها سازگار بمانند.
