# دسترسی، امنیت و بازیابی نمونه

این سند کنترل‌های مرحلهٔ ۸ را برای نمونهٔ مستقل Django توضیح می‌دهد. این کنترل‌ها برای یک ارائهٔ قابل اعتماد مناسب‌اند، اما جای ارزیابی امنیتی، پایگاه‌دادهٔ عملیاتی، مانیتورینگ و برنامهٔ تداوم کسب‌وکار محصول واقعی را نمی‌گیرند.

## حساب‌ها و نقش‌های محلی

دستور `python manage.py seed_demo` چهار گروه و حساب زیر را نیز می‌سازد. گذرواژهٔ پیش‌فرض محلی `Demo-1405!` است و می‌توان پیش از ساخت یا بازنشانی حساب‌ها، `ERP_DEMO_PASSWORD` را تنظیم کرد.

| حساب | نقش | محدوده |
|---|---|---|
| `manager` | مدیر | داشبورد، گزارش‌ها، همهٔ جریان‌ها و دفتر ممیزی |
| `sales` | فروش | مشتریان، کالاهای مرتبط و جریان سفارش فروش تا دریافت |
| `purchase` | خرید | تامین‌کنندگان، پیشنهاد تامین و جریان سفارش خرید تا پرداخت |
| `warehouse` | انبار | موجودی، دفتر گردش، اصلاح موجودی و تحویل/دریافت سفارش تاییدشده |

برای ساخت حساب‌های جاافتاده یا بازنشانی گذرواژه‌ها:

```powershell
$env:ERP_DEMO_PASSWORD = 'یک-گذرواژه-قوی-محلی'
.\.venv\Scripts\python.exe manage.py seed_demo_users --reset-passwords
```

کنترل دسترسی هم در منو و دکمه‌ها و هم در view سمت سرور انجام می‌شود. کاربر ناشناس به صفحهٔ ورود هدایت می‌شود و دسترسی خارج از نقش با پاسخ 403 رد می‌شود. عملیات حساس با CSRF محافظت می‌شوند.

## ردپای ممیزی و اجرای تکراری

تایید و لغو سفارش، تحویل/دریافت، صدور صورتحساب، دریافت/پرداخت، اصلاح موجودی و تغییر اطلاعات پایه با کاربر، زمان، نوع سند و جزئیات در «رویدادهای ممیزی» ثبت می‌شوند. این فهرست فقط برای مدیر و به‌صورت فقط‌خواندنی است.

سرویس‌های مالی و انبار داخل تراکنش اجرا می‌شوند و رکوردهای موثر را با `select_for_update` قفل می‌کنند. محدودیت‌های یکتا از تحویل و صورتحساب دوم جلوگیری می‌کنند. فرم وجه نیز یک شناسهٔ یکتای درخواست دارد؛ ارسال دوبارهٔ همان فرم فقط همان پرداخت قبلی را برمی‌گرداند و مبلغ را دوباره ثبت نمی‌کند. SQLite نوشتن را در سطح پایگاه‌داده سری می‌کند؛ برای محصول چندکاربرهٔ واقعی باید همین آزمون‌ها روی PostgreSQL نیز اجرا شوند.

## تنظیمات محلی و استقرار

- `config.settings_local` فقط برای رایانهٔ محلی است؛ `DEBUG` روشن و کلید آن عمداً عمومی است.
- `config.settings_deploy` برای استقرار است؛ `DEBUG` خاموش است، کوکی امن، HTTPS، HSTS و هدرهای امنیتی فعال‌اند و هیچ کلید محرمانه‌ای در کد ندارد.

نمونهٔ تنظیم استقرار:

```powershell
$env:DJANGO_SETTINGS_MODULE = 'config.settings_deploy'
$env:ERP_DEMO_SECRET_KEY = 'یک-کلید-تصادفی-طولانی'
$env:ERP_DEMO_ALLOWED_HOSTS = 'erp.example.com'
$env:ERP_DEMO_DATABASE = 'D:\erp-data\db.sqlite3'
python manage.py check --deploy
```

HSTS preload فقط برای دامنه‌ای استفاده شود که تمام زیردامنه‌های آن همیشه HTTPS هستند. برای محصول واقعی، سرویس WSGI مناسب، PostgreSQL، محدودسازی نشست، ثبت لاگ خارج از پایگاه‌داده و مدیریت secret توسط زیرساخت لازم است.

## پشتیبان‌گیری و بازیابی

پشتیبان شامل کل پایگاه‌داده، حساب‌ها، داده‌های کسب‌وکار و ممیزی است. دستور پشتیبان از API آنلاین SQLite استفاده و سپس `integrity_check` اجرا می‌کند:

```powershell
.\.venv\Scripts\python.exe manage.py backup_demo
.\.venv\Scripts\python.exe manage.py backup_demo D:\erp-backup\demo.sqlite3 --overwrite
```

برای بازیابی، ابتدا سرور را متوقف کنید. فایل پیش از جایگزینی پایگاه‌داده اعتبارسنجی می‌شود:

```powershell
.\.venv\Scripts\python.exe manage.py restore_demo D:\erp-backup\demo.sqlite3 --yes
.\.venv\Scripts\python.exe manage.py check
```

پس از بازیابی، با هر چهار نقش وارد شوید و تعداد سفارش‌ها، ماندهٔ یک کالا و آخرین رویداد ممیزی را کنترل کنید. آزمون خودکار پروژه نیز یک دور ساخت، تغییر منبع و بازیابی از نسخهٔ پشتیبان را اجرا می‌کند.
